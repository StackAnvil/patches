# Bedrock compatibility status

StackAnvil targets Bedrock **1.26.60 / protocol 2225** and Java **26.3**.
This page describes current support and known gaps. It is not a change log.
Read the [source guide](bedrock-development-sources.md) before using evidence from another build.

## Ownership

| Project        | Responsibility                                                                                |
| -------------- | --------------------------------------------------------------------------------------------- |
| ViaBedrock     | Protocol, authoritative state, inventory requests, resource conversion, and Java translation. |
| Bedrock add-on | Native input, local physics, rendering, audio, and authored UI on the Java client.            |
| ViaProxy       | Preserve negotiated state and resources across the proxy route.                               |
| CubeConverter  | Convert supported Bedrock geometry and materials.                                             |

## Current status

A production implementation is not proof of native parity.
A successful unit test establishes only the behavior it exercises.
Native comparisons apply to their recorded build, fixture, and connection route.
No complete area has verified Bedrock parity.

| Area | Implemented behavior | Remaining limits |
| --- | --- | --- |
| Protocol 2225 | Updated packet layouts, explicit enum values, stonecutter notifications, cursor drags, skin identity, and sound unions. | Block seating, primitive-shape overlays, signed content playback, matchmaking UI, and environment layers remain partial or unsupported. |
| World resources | World base-game version selects vanilla metadata, textures, actor graphs, and audio before server overrides. The context survives ViaProxy. Server legacy biome bindings retain unqualified names across versions. Core rejects pack archives that expand past 1 GiB, stops a connection's pack downloads at 1 GiB in total, and rejects images larger than 4096 × 4096 pixels. The converted-pack disk cache keeps 1 GiB and evicts the least recently used packs. | Native current/older/current cat, sound, and remote biome-name controls cover selected paths. Broader pose and audio behavior need comparisons. The native client has no matching pack size limit, so these bounds sit well above the largest recorded server pack. |
| Held block placement | Retained stationary build paths, next-cell ray selection, independent fresh block/air admission, frame retries after rejection, use timing, trapdoor orientation, cancellation, and prediction. Repeats follow native pacing: 300 ms while sneaking, at most 180 ms while moving, and a 100 ms floor outside Creative. A target outside the build height restarts the repeat timer like a success. | Native, direct, and proxy controls cover selected stationary paths, first rejection, last-stack placement, activation, re-aiming, and release. Moving repeats and height retries rest on static evidence. Live build-height limits, air/entity dispatch, and broader input scheduling remain open. |
| Fonts and UI | Native bitmap metrics and italic geometry, authored scenes and chat notifications, TrueType cache and atlas sampling, primary font aliases, and OreUI shaping, glyph pipelines, and original animation decoding. Layout sizes follow the native solver: a size in a dependency cycle keeps its stored size, 0 for a new control, instead of rejecting the screen, and sizes clamp to -32768..32767. | Selected bitmap and TrueType controls match at 1280 × 720. [Validation and limits](../patches/viafabricplus-bedrock/upstreamable/0029-share-native-ui-scene-rendering.pr.md). Complete screens, OreUI layout and fallback, bold and shadowed text, other font families, mixed or scaled aliases, and broader viewports remain open. |
| Death screen | The death screen opens whenever the spawned local player dies, with or without DeathInfo. The last reason stays until the next DeathInfo replaces it. [Reasons follow the visibility game rule](../patches/viabedrock/upstreamable/0111-honor-death-message-visibility.pr.md), and late reasons [update the current screen](../patches/viafabricplus-bedrock/upstreamable/0042-retain-bedrock-death-screen-lifetimes.pr.md). The screen [follows the native stages and controls](../patches/viafabricplus-bedrock/upstreamable/0042-retain-bedrock-death-screen-lifetimes.pr.md) and [stays above server forms](../patches/viafabricplus-bedrock/upstreamable/0048-keep-the-bedrock-death-screen-above-server-forms.pr.md). | The screen is Java's. Native OreUI layout, fonts, animation, and activation timing remain unfinished. |
| Signs | Undyed signs keep formatting colors. Dyed signs draw all text in the dye color. Each face keeps its first 512 UTF-8 bytes. On Bedrock connections, words wrap across four shared rows, 89 units wide on standing signs and 60 on hanging signs, and a word wider than a row breaks with a hyphen. | Wrapping rests on static evidence without an in-game capture. Hyphenation assumes the English default. Continuation rows keep formatting without `PersistFormatting`, where native may drop it. Formatting colors on unlit signs are slightly brighter than native. |
| Player inventory and crafting | Opening ownership, recipe catalogs, Creative catalog actions, Survival bulk and manual crafting actions, retained recipe queries, compressed snapshots, local Help, inactive item lighting, native storage weights, desktop bundle insertion/default extraction, and native stack identities. | Complete E-key/workbench presentation, bundle controller input and rendering, search across server transfers, recipe families beyond the captured controls, and the original live reports remain unresolved. See the [inventory reference](native-player-inventory.md). |
| Containers | A reopen with the same menu type and ID keeps the open menu and sends no close. A container open at a loaded block that is not a chest, ender chest, shulker box, or barrel opens nothing. Menus with named slots, such as anvils and smithing tables, reconcile drags and responses by storage slot. Crafting tables that reuse the player UI's container ID 124 keep their own cursor prediction. An unanswered player-inventory open stops blocking later screens after 10 seconds. | A container open in a missing or pending chunk still opens a menu, because the native deferral rules are not established. Native handling of an unanswered open is not established either. |
| Food use | Native food components govern admission and use. Local completion predicts hunger while inventory counts remain server-owned. Changing the selected hotbar slot ends use, even when the new slot holds the same food. | Selected admission and use controls pass. Correction replay preserves live hunger on both Java routes. Broader movement timing and the original intermittent report remain open. See the [food-use evidence](../patches/viabedrock/deferred/0008-signal-sustained-bedrock-item-use.pr.md). |
| Cooking | Snapshot-bound recipe and bundle actions, transfer batches, preferences, search, and progress. | Default cooking screens retain ordinary controls until authored bindings are complete. See the [cooking reference](native-cooking-actions.md). |
| Skins and appearance | Skin transport, classic changes, custom and 4D skin packs, saved skins, persona assembly, animation graphs, costumes, attachables, and [native patterned shields](../patches/viafabricplus-bedrock/upstreamable/0017-render-equipped-native-pack-models.pr.md). A skin that disables attachables draws none in any slot and skips their `parent_setup` scripts. `hide_armor` hides armor attachables, and `context.item_slot` uses the native slot names. | Custom wearable items still draw when `hide_armor` is set. Broader wardrobe masking, profile/LOD changes, remote appearances, and account/platform flows need further native comparisons. See [skin support](skin-flow.md). |
| Camera | Core-resolved poses, follow targets, blends, FOV commands, shake, fades, native ordinary player FOV, and the default death view. See [camera validation](../patches/viafabricplus-bedrock/upstreamable/0023-render-core-resolved-camera-movement.pr.md). | Selected stationary projections, swim-boost expiry, and settled death views have native comparisons. Death activation timing, varied angles and postures, other fluid effects, portrait scaling, transition timing, collision, aim assistance, and complete visual parity remain open. |
| Mounts and vehicles | Only boats and tamed, saddled horses, donkeys, mules, skeleton horses, and zombie horses are client-predicted, and only for the rider in the controlling seat. Other ridden mounts, such as camels, llamas, saddled pigs, striders, nautili, and happy ghasts, follow server positions while the rider keeps Java controls. Predicted horses use the native step height of 1.0625, or 0.5625 on honey, and ease their yaw toward the rider. | Boats keep Java boat motion. Owned BDS water-boat controls cover forward movement, impulses, teleports, dismount, and remount on both routes. Native trajectories, horses, other seats, live riding of server-driven mounts, and adverse networks remain unverified. |
| Movement and effects | Completed physics frames, retained prediction history, correction replay, terrain queries, and authoritative impulses. [Local modes survive profile refreshes and physics replay](../patches/viafabricplus-bedrock/upstreamable/0025-send-completed-local-physics-to-viabedrock.pr.md). [Remote-player live and sparse movement origins remain separate](../patches/viabedrock/upstreamable/0106-align-retained-remote-spawn-origins.pr.md). [Negotiated remote movement retains native float steps, pitch history, and head targets](../patches/viafabricplus-bedrock/upstreamable/0041-interpolate-native-remote-player-movement.pr.md). Like native, core applies corrections only through replay and drops one that no retained frame can replay. Near teleports carry the MovePlayer ground state. Liquids push once per tick, and lava wins over water. Motion prediction hints are ignored, as in native. Strafing sends Bedrock's axis signs. Overworld air blindness attenuates night-vision strength and fog color together. Both Java routes match native water-boundary fall controls. | Selected reset, head, body, and queued-movement controls match native after packet/tick state alignment. Full trajectories, pose parity, readiness, ground state, and exact timing still need native comparisons. Strafing signs rest on static evidence. Other fluid movement, vision combinations and media, network conditions, and broader replay behavior remain open. |
| Fog and picking | Fog commands, inherited legacy biome bindings, pack-defined defaults, Overworld clock modulation, End dragon distance rules, native actor picking transport, and native float camera rays. Disabling the daylight rule freezes explicit Overworld clocks. Air fog averages 27 weighted biome samples around the camera, moves 1% toward its target each frame, and ends within the native render-distance margin. | Both routes match selected native fog colors and distances, three non-cardinal rays, and paired armor-stand and block reach controls. Eye precision, other actor shapes, multipart target ordering, timed command transitions, directional sunrise tint, End sky sampling, the stricter submerged-camera cap, fluid and weather fog, and other render modes remain open. |
| Locator bar | Core follows the native locator rules: it ignores updates before join, creates groups only from complete additions, stops at a missing required field, and shows a player only while a visible group is bound to them. The add-on draws groups with native bearing, size, and smoothing. It uses accepted pack images, then the bundled vanilla images, and keeps Java's bar only when neither provides the background. | Native, direct, and ViaProxy player-marker controls agree on presence, removal, and restoration. Legacy-only player updates, full HUD definition overrides, custom textures, vertical arrows, and complete layout remain unverified. |
| Lighting | Native lightmap in supported vanilla dimensions on direct Bedrock sessions and proxy sessions with an accepted converted server pack. Native skylight filtering for slabs, stairs, and waterlogged blocks, custom light filters, and `face_dimming: false`. Bedrock sessions omit Java's low-light vignette. Actors keep `ignore_lighting`, light color multipliers, and bone material overrides. | The End keeps Java's lightmap. Emissive-alpha materials and lit directional actor shading use fallbacks. Ambient occlusion, Vibrant Visuals, ray tracing, sky gradients, clouds, and held-item shading are not native. The lightmap port's binary findings come from 1.26.51.1 and need [REA](bedrock-development-sources.md#analyze-a-native-artifact-with-rea) confirmation. |
| Custom content | Resource-defined actors, materials, particles, sound, block geometry, lighting, and collision. Verified base-factory blocks and hardcoded primary providers retain [camera bounds without visual models](../patches/viafabricplus-bedrock/upstreamable/0017-apply-custom-block-shapes.pr.md). Armor stands receive the native frame and hurt-time queries, so they draw through their native resources and wobble when hit. | Unsupported material methods, missing assets, carrier capacity, legacy texture-array variation, nonuniform scaling of rotated cubes, double-sided alpha-test back faces, and a second water layer on carriers without fluid support remain. Visual differences remain. Live-server admission does not establish parity. |
| Platforms | Linux build, replay, and selected native comparisons. | Windows and macOS launcher/account/rendering paths need their own results. See [platform testing](platform-testing.md). |

## Reported regressions

Retain these reports until a matching reproduction establishes the result:

- Lifeboat dialog text was reported as untranslated. Captured Navigator titles, captions, and response indices survive both [Java dialog projection](../patches/viabedrock/upstreamable/0095-share-native-ui-programs-and-resources.pr.md) and [add-on render failures](../patches/viafabricplus-bedrock/upstreamable/0029-render-authored-forms-and-npc-dialogs.pr.md). These controls preserve the official 1.26.60.5 scene bytes. The original reported dialog remains unmatched.
- Lifeboat's opaque player-head obstruction matches a missing native near-camera fade. World player materials use the [native ordered fade](../patches/viafabricplus-bedrock/upstreamable/0002-native-entities-and-skins.pr.md). GPU checks cover color and depth through native and Iris programs. A matching offline scene reveals the lobby through nearby players. Broader spawn and rendering parity remain open.
- WildFFA inventory opened with E shows items without the expected background.
- An update from 0.3.61 to 0.4.2 caused reported inventory lag spikes and overlapping menus.
- The 0.4.3 bed-floor report matches a reproduced [MoreCulling interaction](../patches/viafabricplus-bedrock/upstreamable/0040-preserve-native-occlusion-with-moreculling.pr.md). Current direct and proxy controls preserve the floor. The affected player's mod list remains unknown.
- An ender pearl followed by a wind charge can cause repeated rollbacks. Core used to snap to a correction that the add-on could not replay. The add-on then cleared its replay history, so the next correction took the same path. Core now [drops such corrections](../patches/viabedrock/upstreamable/0092-retain-completed-client-prediction-frames.pr.md) and waits for one that a retained frame can replay. Selected [native and Java controls](../patches/viafabricplus-bedrock/upstreamable/0025-send-completed-local-physics-to-viabedrock.pr.md) settle, including walking projectile combinations with added incoming delay. The persistent loop on the reported server remains unmatched.
- Food can repeat its use animation without feeding the player. Java kept eating after a switch to another slot that held the same food, but the server never fed the player. Use now ends on any slot change. The original report remains unmatched.
- The locator bar can be absent. The add-on replaced the Java bar but drew nothing when no accepted pack provided its images, for example after a declined pack. It now falls back to the bundled vanilla images. Current native, direct, and ViaProxy [player controls](../patches/viafabricplus-bedrock/upstreamable/0022-render-native-locator-groups.pr.md) display markers and remove or restore them after rule changes. The reported server remains unmatched.
- A Realms disconnect report shows NetherNet connectivity loss and repeated STUN 401 responses. Current networking updates still need a matching reproduction.

Release fixes and successful local controls do not close an unmatched report.
Record the client build, mods, server, input path, and reproduction with a new result.
